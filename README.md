# Preference Experiment 🧬

This project investigates whether Large Language Models (LLMs) exhibit a preference for text they generated themselves compared to text generated by other models. It provides a framework for generating responses to prompts across multiple models, rating those responses using various LLMs, and performing statistical analysis on the results.

## 🚀 Key Features

- **Multi-Model Generation**: Generate responses from several LLMs to a common set of prompts.
- **Cross-Model Rating**: Use LLMs as judges to evaluate and rank responses.
- **Statistical Analysis**: Automatically calculate win rates and identify self-preference biases.
- **Extensible**: Easily add new models or evaluation criteria.
- **Mock Mode**: Test the entire pipeline without hitting external APIs.

## 📋 Prerequisites

- [Python 3.10+](https://www.python.org/)
- [uv](https://github.com/astral-sh/uv) (recommended) or `pip`

## 🛠️ Installation & Setup

1. **Clone the repository**:
   ```bash
   git clone https://github.com/yourusername/PreferenceExperiment.git
   cd PreferenceExperiment
   ```

2. **Install dependencies**:
   ```bash
   uv sync
   ```

3. **Configure Environment Variables**:
   Copy the example environment file and add your [OpenRouter](https://openrouter.ai/) API key:
   ```bash
   cp .env.example .env
   ```
   Then edit `.env` to include your key:
   ```env
   OPENROUTER_API_KEY=your_openrouter_key_here
   USE_MOCK=False
   ```

## 📖 Usage

Run the experiment pipeline in three main steps:

1. **Generation**: Create responses from all configured models.
   ```bash
   uv run main.py generate
   ```

2. **Rating**: Evaluate the generated responses.
   ```bash
   uv run main.py rate
   ```

3. **Analysis**: Calculate statistics and visualize results.
   ```bash
   uv run main.py analyze
   ```

4. **Combine Runs**: (Optional) To analyze results across multiple experimental runs:
   ```bash
   # Automatically finds all results/run* folders
   uv run combined_analysis.py
   
   # Or specify folders manually
   uv run combined_analysis.py results/run1 results/run2
   ```

## ⚙️ Configuration

The project configuration is managed in `config.py`. You can modify:
- `MODELS`: The list of LLMs involved in the experiment.
- `PROMPTS`: The list of evaluation prompts to generate responses for.
- `USE_MOCK`: Set to `True` for testing without API costs.

## 📁 Project Structure

- `main.py`: CLI entry point.
- `experiment.py`: Core logic for orchestrating generation and rating.
- `llm_client.py`: Wrapper for LLM interactions.
- `config.py`: Central configuration and constants.
- `storage.py`: Data persistence layer (JSON-based).
- `analysis.py`: Statistical calculation logic.

**Note**: All experimental results and generated reports are stored in the `results/` directory.
